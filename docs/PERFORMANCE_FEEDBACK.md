# 성과검증 → 종합추천 (2026-09-08)

사용자 요청에 따라 프로젝트별 최초 추천일을 고정하고 매일 수익률을 계산한다.
기준은 최초 추천일 수정종가이며 휴장일 추천은 다음 거래일 수정종가이다.
N거래일 성과는 기준 종가에서 N개 거래일이 지난 종가까지 계산한다.
반복 추천, 순위 변경, 엔진 버전 변경으로 최초 날짜를 초기화하지 않는다.

과거 data.json Git 저장본은 종목코드가 확인된 기록만 복원한다. 저장시각과
실제 사이트 공개시각은 구분하며 공개시각을 추정해 넣지 않는다. 확인되지 않은
더 오래된 추천일도 만들지 않는다. 당시 순위·조건·규칙·원본 행을 보존한다.

종합추천은 최근 각 프로젝트 표시 후보의 합집합에서 선정한다. 진입은 필수조건이 아니다.
프로젝트 중복, 진입상태, 순환단계/선행관계, 정상화 가치 구간/섹터할인,
성장 주가반응에서 1~3개 공통조건을 분석한다. 기록 당시 존재했던 조건만 사용한다.

현재 추천 가격일보다 앞서 평가가 끝난 20일, 5일, 1일 성과 순으로 최소 3개 표본이
있는 가장 긴 기간을 사용한다. 패턴별 최소 3개 고유종목을 요구한다. 종목/추천일
중복을 제거하고 패턴 내 같은 종목은 평균하여 한 표본으로 계산한다.
반영점수 = 중앙 수익률 × 고유종목 수 / (고유종목 수 + 10).
평균과 중앙 수익률이 모두 양수인 패턴만 추천에 사용한다. 한 종목의 여러
중첩 패턴 점수를 더하지 않고 가장 높은 일치 점수 하나를 사용한다.
동점은 프로젝트 중복 수, 현재 프로젝트 평균 순위, 종목코드 순이다.
표시 목표는 최대 10개이며 조건 부족 시 억지로 채우지 않는다.

소표본, 이전 규칙, Git 복원 성과가 포함되며 별도 미래 성능 검증 전의 탐색 규칙이다.
고유종목 10개 미만 또는 추천일 3개 미만이면 초기 관찰로 표시한다.
현재까지 수익률은 경과기간이 다를 수 있으므로 모델 학습에는 쓰지 않는다.
과거 전체시장 구성 검증 전 시장 대비 수익률은 미표시한다.

refresh_all.py는 매일 성과를 먼저 계산한 뒤 새 종합추천을 만든다.
refresh_research.py는 게시 원본 표를 바꾸지 않고 연구 부분만 재계산한다.
promote_sections.py --research-only는 게시 원본 회차/가격일/스냅샷 일치를 검증한다.
배포 후 record_publication.py로 실제 공개를 확인하고 새 추천 회차를 기록한다.

기존 REFRESH_AND_PERFORMANCE.md의 다음 거래일 시가/고정 교집합 규칙은
legacy 규칙으로 남으며 현재 운영 규칙은 이 문서와 performance_feedback.py이다.
