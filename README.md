# stock-scoreboard 전체시장 보드 엔진

KOSPI+KOSDAQ 전체 종목을 수집한 뒤 `p11` 순환, `p1` 진입, `p2` 가치를 서로 다른 기준으로 계산합니다. `p12` 단타는 테스트 보드에서 삭제됩니다. 기존 `data.json`은 **읽기만 하고 절대 수정하지 않습니다.** 모든 결과는 `test_output` 폴더에 따로 생성되며 배포 기능은 없습니다.

## 가장 쉬운 테스트

1. 이미 Python 데이터 패키지가 있으면 `run_test.bat`를 더블클릭합니다. 처음 실행에서 패키지 오류가 나오면 `setup_windows.bat`를 한 번 실행합니다.
2. 끝나면 `test_output/data.test.json`과 `collection_report.test.json`을 확인합니다.

샘플 모드는 인터넷과 외부 시세 라이브러리가 없어도 실행되며, 같은 입력으로 항상 같은 결과를 만듭니다.

## 실제 전체시장 데이터로 실행

1. Python 3가 설치된 Windows에서 `setup_windows.bat`를 한 번만 더블클릭합니다.
2. 이후에는 `run_screener.bat`만 더블클릭합니다.
3. 결과는 `test_output/data.test.json`과 `test_output/p11.test.json`입니다.

실행 중 원본 `data.json`의 SHA-256을 앞뒤로 비교합니다. 조금이라도 바뀌면 오류로 종료합니다.

## 데이터 소스와 장애 대응

- 1순위 `pykrx`: KOSPI+KOSDAQ 종목 목록, KRX 업종 분류, 날짜별 전 종목 OHLCV/거래대금을 일괄 조회합니다. 종목별 수천 번 호출하지 않고 거래일별 약 80번 호출하는 구조입니다. 익명 접근이 차단된 환경에서는 즉시 다음 소스로 전환합니다.
- 캐시: 정상 수집한 전체 데이터를 `cache/krx_prices.csv.gz`에 저장합니다. 30시간을 넘긴 캐시는 정상 자료처럼 사용하지 않습니다.
- 2차 대체 `FinanceDataReader + yfinance`: KRX 설명형 목록의 `Industry`와 `.KS`/`.KQ` 가격을 묶음 조회합니다. 화장품·반도체·2차전지·전력기기·전선·조선·방산 등 핵심 순환 테마는 회사명·업종·주요제품 키워드로 보정합니다.
- 재시도: 외부 호출은 기본 3회, 점증 대기 후 다음 소스로 넘어갑니다.
- 검증: 최신일 커버리지 98%, KOSPI·KOSDAQ 종목 수, 미분류 비율, 최신 가격일을 따로 기록합니다. 누락 종목은 `missing_stocks.test.json`에 기록하며 실패를 `변경 없음`으로 표시하지 않습니다.
- 컨센서스: 기본값은 운영용 `consensus_cache.csv`입니다. 무료 대안으로 한국투자증권의 공식 KIS Developers `종목추정실적` API를 연결할 수 있습니다. 이 자료는 약 160개 추정 대상 기업에 한정되고 월초 애널리스트 의견 기준이므로, 전 종목·실시간 컨센서스로 표시하지 않습니다. 없거나 오래되면 임의 수치로 채우지 않고 사유·기준일을 표시합니다.
- 공시 성장률: Windows 사용자 환경변수 `DART_API_KEY`가 있으면 OpenDART의 최신 반기·분기·연간 공시에서 전년 동기 매출과 영업이익 성장률을 수집합니다. 컨센서스가 없어도 공시 성장률 종목을 제외하거나 감점하지 않습니다. 실패 종목은 `test_output/dart_failures.test.json`에 기록하고 정상 자료는 24시간 캐시합니다.
- 세부 테마 보정: `sector_overrides.example.csv`에 `종목코드,세부섹터`를 추가하면 KRX 대분류보다 우선 적용됩니다. 운영할 때는 파일명을 복사해 별도 관리해도 됩니다.

무료 비공식 데이터는 장기적으로 형식이나 접근 정책이 바뀔 수 있습니다. 실거래 주문·자동매매용이 아니라 보드 스크리닝용으로 설계했습니다.

## 계산 내용

- 시장 기준: 당일 KOSPI+KOSDAQ 구성 종목의 동일가중 수익률
- 섹터 상대강도: 섹터 동일가중 1일/3일/5일 수익률에서 시장 수익률 차감
- 거래대금 변화: 최근 3일 평균과 그 이전 10일 평균 비교
- 상승종목 비율: 섹터 내 당일 상승 종목 비율
- 선도주 강도: 섹터 상위 20% 종목의 5일 수익률과 시장 5일 수익률 차이
- 확산형/선도주 견인형: 상승 비율·거래대금과 선도주 강도를 독립 평가해 둘 다 포착
- 시작일: 최근 20~40영업일 창에서 종합점수·3일 RS와 확산/선도 조건이 이틀 지속된 최초일을 역산
- 단계: `①초기 ②확산 ③주도 ④눌림 ⑤재반등 ⑥후반 X조기이탈 X종료`
- 주기/위험: 과거 활성 구간 중앙값(부족하면 25일), 현재 경과, 위치 %, 낙폭·집중도·단기 약세 기반 위험 게이지
- 종목 관계: 종목 3일 수익률과 섹터 3일 수익률의 차이로 `선행/동행/후행`
- 진입: 전체 내부 종목에서 과열·후반·종료를 제외하고 추세, ATR 진입구간, 거래량 확인을 거쳐 `진입가능/곧진입`만 표시
- 가치: 영업이익 성장률 70%와 매출 성장률 30%를 기본 순위로 유지합니다. KIS 예상 영업이익 성장 방향과 1·5·20일 추정치 변화를 합산하되 최대 ±10점의 보조값으로만 반영하며, 미제공 종목은 0점 조정으로 원래 성장순위를 유지합니다.

상세 수치는 기존 화면이 무시해도 되는 추가 JSON 필드로 넣었습니다. 기존 화면이 요구하는 `rank/name/stage` 및 행 필드도 유지합니다.

## 명령줄 사용(선택)

```powershell
python rotation_screener.py --mode sample
python rotation_screener.py --config config.example.json
python -m unittest discover -s tests -v
```

## 무료 KIS 컨센서스 연결

한국투자증권 KIS Developers에서 무료 앱키를 발급받은 뒤 Windows 환경변수 `KIS_APP_KEY`, `KIS_APP_SECRET`에 넣습니다. 키는 파일이나 GitHub에 저장하지 않습니다. 이후 `run_kis_screener.bat`만 더블클릭하면 됩니다. 앱키가 없으면 친절한 안내 후 종료하며, 일반 `run_screener.bat`에는 영향을 주지 않습니다.

첫 실행부터 2천여 종목을 호출하지 않습니다. 거래대금 상위와 기존 캐시를 우선 갱신하고, 나머지는 실행할 때마다 250종목씩 순환 탐색합니다. 성공한 종목만 `cache/kis_consensus_cache.csv`에 보존하고, 미제공·실패 종목은 `test_output/consensus_failures.test.json`에 따로 기록합니다. 가격 기준일과 컨센서스 기준일은 서로 독립적으로 표시됩니다.

KIS 공식 설명상 추정실적은 월초 기준이므로 매일 값이 바뀌지 않을 수 있습니다. 호출 실패는 `변경 없음`으로 처리하지 않으며, 이전 정상값은 원래 기준일과 함께 남깁니다.

## 파일 안내

- `rotation_screener.py`: 데이터 수집, 캐시, 계산, 단계 판정, JSON 생성
- `config.example.json`: 조회·캐시·출력 설정 예시
- `sector_overrides.example.csv`: 세부 섹터 수동 보정 예시
- `run_test.bat`: 오프라인 샘플 테스트
- `setup_windows.bat`: 최초 1회 환경 준비
- `run_screener.bat`: 실제 전체시장 실행
- `run_kis_screener.bat`: 전체시장 실행 + 무료 KIS 추정실적 순차 갱신
- `config.kis.example.json`: KIS 컨센서스 연결 설정
- `tests/test_engine.py`: 순환·진입·가치·수집검증 테스트
- `test_output/*.test.json`: 테스트 결과(실행 후 생성)

## 현재 보드에 적용할 때

이번 작업에서는 적용·배포하지 않습니다. 검증이 끝난 뒤에만 `test_output/data.test.json`의 `p1/p11/p2`를 운영 데이터에 반영합니다. 이때도 단타 `p12`는 제거하고, 수집 보고서의 실패 영역은 이전 정상값과 기준일을 보존한 채 명시해야 합니다.
